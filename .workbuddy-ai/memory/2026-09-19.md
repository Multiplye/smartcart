## Bugfix: `npm run dev` -> "Missing script: dev"

**Cause:** there are TWO nested folders both named `smartcart`. The user ran
`npm run dev` in `smartcart/smartcart/`, which only contains a Tailwind-only
`package.json` (deps: `@tailwindcss/vite`, `tailwindcss`) with **no scripts**.
The real React app is in the innermost `smartcart/smartcart/smartcart/`.

- Wrong: `smartcart/smartcart/`          -> `npm error Missing script: "dev"`
- Right: `smartcart/smartcart/smartcart/` -> works

**Fix applied:** documented, not restructured (did not move folders — too risky
for the user's working setup). Added:
- `HOW-TO-RUN.md` at project root — exact copy-paste commands for both servers,
  a folder-layout diagram, an error/fix table.
- `smartcart/smartcart/README-WRONG-FOLDER.md` — signpost in the wrong folder.

**Verified working:** backend on 127.0.0.1:5000 (30 products, CORS OK),
frontend on localhost:5173, full stack fetch confirmed.

### Other gotchas found
- Vite 8 binds **IPv6 only** (`[::1]:5173`), so `127.0.0.1:5173` refuses the
  connection while `localhost:5173` works. Normal, not a bug — but confusing
  when probing with tools that resolve to IPv4.
- Flask `debug=True` runs a reloader **child process** that does the actual
  serving, so killing the netstat PID can leave the port answering. Verify a
  port is free with `socket.bind()`, not netstat.

instead of a cryptic npm error, and folder 3 still builds and runs normally.

Also updated `HOW-TO-RUN.md` with both errors in the troubleshooting table.

## Bugfix 3: guard rail misfired — npm run inside `backend/`

User ran `npm run dev` from `smartcart\backend\` (prompt showed `(venv) PS ...\backend>`)
and got the **project-root** guard-rail message, which said "you are in the project
root" — inaccurate, since they were in `backend`.

**Why:** `backend/` had no `package.json`, so **npm walks UP the folder tree** and
found the root one, printing the root's message. Important npm behaviour to remember.

**Fix:** added `backend/package.json` with a distinct message that correctly says
"WRONG FOLDER AND WRONG TOOL - this is a Python project, use `python app.py`"
and gives the right relative path to the frontend.

**Error I made and corrected:** my first version of the backend message said
`cd ..\smartcart\smartcart\smartcart` (three levels). The correct relative path
from `backend/` is `cd ..\smartcart\smartcart` (two levels). Caught it by
actually testing the path with `cd` + checking for `vite.config.js` before
trusting it. Lesson: always verify a printed path, don't compute it mentally.

**Final verified state — 4 locations, guard rails correct in all:**
| Folder | `npm run dev` behaviour |
|---|---|
| `smartcart\` (root) | "WRONG FOLDER" + correct cd |
| `smartcart\backend\` | "WRONG FOLDER AND WRONG TOOL" + `python app.py` |
| `smartcart\smartcart\` | "WRONG FOLDER" + `cd smartcart` |
| `smartcart\smartcart\smartcart\` | ✅ Vite starts normally |

Backend confirmed serving 30 products; frontend confirmed starting on 5173.

## Feature: Step 1 — Authentication (User table + register/login)

User chose **simple session model** (not JWT) with the note "simple but unique
type". Passwords ARE properly hashed via werkzeug's `generate_password_hash`
(scrypt) — no extra install, Flask bundles it. Confirmed `password_hash` never
appears in any API response.

### Backend (`backend/app.py`)
- New `User` model: `id, name, email (unique), password_hash, role`
- `ROLES = ["buyer","seller","admin"]`, default `buyer`
- `POST /api/register` -> 201 | 400 (missing field / pw<6 / bad role) | 409 (dup email)
- `POST /api/login`    -> 200 | 400 | 401
- Identical error message for wrong-password and unknown-email (anti user-enumeration)
- Emails stored lowercased -> login is case-insensitive
- Added `user_to_dict()` helper which deliberately omits `password_hash`

### Frontend
- `src/context/` split into 3 files: `AuthProvider.jsx`, `authContextInstance.js`,
  `useAuth.js`. **Split was required by eslint `react-refresh/only-export-components`** —
  a file exporting both a component and a non-component breaks Fast Refresh.
- `src/data/api.js`: added `login()`, `register()`, and a shared `postJson()` helper
  that converts the backend's `{error}` responses into thrown JS Errors.
- `src/components/Auth.jsx`: rewired to the real API. Kept the original markup/CSS
  classes. Added role dropdown, confirm-password check, error/success banners,
  submitting state, and a logged-in view with Log Out.
- `src/main.jsx`: wrapped in `<AuthProvider>`.
- `src/App.jsx`: navbar shows `Hi, <first name>` when logged in; removed a
  pre-existing unused `heroImage` import.
- `src/App.css`: styled `select` to match inputs, plus `.auth-message`,
  `.auth-error`, `.auth-success`, `.auth-btn:disabled`.

### Verified

- Live HTTP test against 127.0.0.1:5000: register 201, login 200,
