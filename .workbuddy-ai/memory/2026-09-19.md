### Other gotchas found
- Vite 8 binds **IPv6 only** (`[::1]:5173`), so `127.0.0.1:5173` refuses the

- Flask `debug=True` runs a reloader **child process** that does the actual
  serving, so killing the netstat PID can leave the port answering. Verify a
  port is free with `socket.bind()`, not netstat.

### Keyed-state pattern (replaces setState-in-effect)
Lint rule `react-hooks/set-state-in-effect` fires on a synchronous setState in
an effect (hit it again here). Fix used, and worth reusing:

```js
const [state, setState] = useState({ key: urlValue, value: urlValue });
if (state.key !== urlValue) setState({ key: urlValue, value: urlValue });
const value = state.value;   // re-reads URL on render, no effect needed
```
Store the URL value the state was derived from as a `key`; when the URL changes
underneath, the key mismatches and state re-syncs during render - no cascading
render. Remember to set BOTH the value and its key in any updater, or the guard
immediately undoes the edit.

|---|---|

| `ai-shimmer` | skeleton pulse (opacity, not a gradient sweep - cheaper) |

**Pattern worth reusing - stagger via an inline custom property:**
```jsx
// JSX: delay computed where the index is known
<article className="ai-card-rec" style={{ "--rec-delay": `${delay}ms` }}>
```
```css
/* CSS: one rule, no nth-child chains, any list length works */
.ai-card-rec {
  opacity: 0;
  animation: ai-card-in 0.5s cubic-bezier(0.22, 0.61, 0.36, 1) forwards;
  animation-delay: var(--rec-delay, 0ms);
}
```
This avoids `:nth-child` delay lists and keeps the stagger in the component.
Delay is capped (`Math.min(index, 8) * 70`) so a long list never makes the last
card wait a silly amount of time.

**Important:** every animated element must set `opacity: 0` in its own rule, and
the animation must be `forwards` - otherwise the element is invisible or flashes.
The existing global `prefers-reduced-motion` block already sets
`animation-duration: 0.01ms !important`, which neutralises all of this for users
who ask for less motion. No extra work needed for accessibility.

## Step 13c - heading font -> Playfair Display (commit 81c6baf)

User: "i need you to keep me pick for you text in another suitable text font".

### The real diagnosis
The heading was `font-family: "Poppins"` with `<span>` set to
`font-style: italic`. **Poppins has NO italic face.** Google Fonts only serves
Poppins in normal style, so the browser was **synthesising** the italic by
skewing the roman glyphs. That mechanical slant is why "For You" looked weak
and cheaper than the upright "Picked" beside it.

**Rule to remember for this project:** as of this commit only two families are
loaded - **Inter** (body) and **Poppins** (headings/buttons). **Neither has a
true italic.** Any `font-style: italic` on those two is a fake slant. If an
italic is wanted, the family must be changed or added, not just the style.

### The fix
Added **Playfair Display** with the `ital,wght` axes:
`family=Playfair+Display:ital,wght@0,500;0,600;1,500;1,600`

Applied only to `.rec-header h1`. It is the **only serif** on the page, so it
reads as an accent rather than an inconsistency, and it has a genuine italic.

Adjustments that must go with the face swap (do not revert these independently):
| Property | Was (Poppins) | Now (Playfair) | Why |
|---|---|---|---|
| weight | 700 | 600 | high-contrast display face goes heavy fast |
| letter-spacing | -0.03em | -0.01em | a serif needs its natural rhythm |
| size | clamp(2rem, 4vw, 3rem) | clamp(2.15rem, 4.4vw, 3.35rem) | smaller apparent x-height |
| line-height | 1.12 | 1.14 | serif needs a touch more air |

### Verification done (and why it mattered)
Checked the **Google Fonts URL directly** with a browser user-agent:
`curl -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"` -> HTTP 200, returning
**2 normal + 2 italic faces** at weights 500/600. This was worth doing because
a bad `@import` fails **silently** - the browser just falls back to Georgia and
the page looks subtly wrong with no error anywhere. Note Google Fonts returns
an empty/404 body to a default curl user-agent, hence the `-A` flag.

### Verified
