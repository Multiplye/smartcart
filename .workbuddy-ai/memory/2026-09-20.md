## Step 27 - Rounded search pill + products page polish

User: *"make a litle bit curve on the search bar in the product and if you can
add anything in this webpage pic or anything you can add to look it better"*.

### What changed

**The search bar is now a real pill.** It was `border-radius: 10px` with the
input and the Search button as two separate rounded boxes. Now:

- `.search-form` is the pill: `border-radius: 999px`, background `#f4f8fb`,
  2px transparent border, with the input and button *inside* it. The input
  has `background: transparent` and no border of its own, so there is no
  seam between the two.
- Magnifier icon drawn with a **CSS mask** (`--search-icon` data URI in
  `:root`) rather than an image file. It inherits colour from `background`,
  so focus just switches it to `--purple`.
- `:focus-within` on the form lights the whole pill up. The focus ring would
  otherwise only appear around the bare input inside it.
- Hidden `::-webkit-search-cancel-button` — Chrome's own clear "x" sits on
  top of the pill padding, cannot be restyled, and duplicates the Clear button.

909px radius is used instead of half the height (`999px`) so it stays a pill
at any height; a fixed number would square off when the font scales.

**The controls moved onto their own card.** `.filter-bar` is now a white card
with `margin: -46px auto 0` so it overlaps the blue page header above, plus a
soft shadow. Previously the controls sat in the gap below the header with
nothing anchoring them. Header got `padding-bottom: 118px` to absorb the overlap
and two decorative white circles (`::before`/`::after`) for texture.

**Chips went from black to brand purple.** `#111111` was the only non-palette
colour left on the page and made the selected filter look like a disabled
button. Now `--purple` with a soft glow.

**Result count moved to the end of the chip row** (`.filter-row` flex wrapper)
so it reads as a count of what the filters produced rather than another control.

### THE BIG LESSON - headless `--window-size` does not set the layout viewport

I burned **three rounds of edits chasing a mobile overflow that did not exist.**

`chrome --headless --window-size=420,900 --screenshot=x.png` renders at the
default *desktop* width and then CROPS the image to 420px. The output looks
exactly like a page whose content overflows right — everything shifted and
clipped. I "fixed" it three times before measuring.

The measurement said: `viewport: 420`, `docScrollWidth: 420`, **zero
offenders**. The CSS had been fine the whole time.

**The correct check is CDP**: launch Chrome with
`--remote-debugging-port`, call `Emulation.setDeviceMetricsOverride`, then read
`getBoundingClientRect` from the page. Scripts written this session:

- `~/.workbuddy-ai/binaries/node/workspace/measure2.js` — reports
  `docScrollWidth` + every element wider than the viewport, by name.
- `~/.workbuddy-ai/binaries/node/workspace/shot.js` — true-layout screenshot.

Pass condition: **`docScrollWidth === viewport` and `offenders` is empty.**
Verified at 420px and 1440px: both clean.

For the screenshot, `Page.captureScreenshot({ captureBeyondViewport: false })`.
With `true` a full-page shot of a 36-product list shrinks to an unreadable sliver.

### Genuine CSS issues that measurement did surface

- **`min-width: 0` on the flex input.** A flex item will not shrink below its
  content size without it. The base `min-width: 180px` was holding the pill
  wider than a 420px viewport.
- **Never stack a pill into a column on mobile.** The old
  `@media (max-width: 600px) { .search-form { flex-direction: column } }`
  turned the pill into a tall capsule whose rounded ends no longer matched the
  controls inside. Kept the row; moved only Clear to its own line with
  `order: 3` + `width: 100%`.
- **Shortened the placeholder.** "Search products by name or description" was
  truncated mid-word on a phone. "Search products" fits everywhere; the full
  wording moved to `aria-label` so screen readers still get it.
- Gave `.filter-bar` side margins on mobile (`margin: -34px 16px 0`) so the
  card's rounded corners are visible instead of bleeding off the screen edge.

### vite.config.js workaround (important to remember)

`build.emptyOutDir: false` was added **because of this machine**, not
because the project needs it. Vite empties `dist` before every build; here
that delete is routed through a trash helper that times out, so the build
died with `[safe-delete] ... ETIMEDOUT` *after* all 46 modules had already
transformed. Worked around by never letting Vite delete anything.
Harmless but unnecessary on a normal machine and on Vercel. Filenames are
content-hashed, so stale files are unlikely; clear `dist` by hand if they
accumulate.

## Step 28 - Home search pill + category card icons

User: *"can you put same search bar in this also same like inside product and

### Home search bar is now the same pill as the products page

The two search bars were the same control with two separate rule sets.
They now **share one rule block** (`.home-search, .search-form { ... }`).
Two copies would have drifted apart the first time one was edited.

`.home-search` no longer appears as a plain block in the flow — it is the
pill itself, with the input and button inside it, `border-radius: 999px`,
the mask-drawn magnifier, and the `:focus-within` purple glow.

The only difference between the two is the surrounding frame:
- `.home-search` sits in the page flow, `max-width: 640px`, centred
- `.search-form` sits inside `.filter-bar`, the white card overlapping the
  products header

Mobile rules at `≤600px` were extended to cover `.home-search` too, plus
`margin: 0 16px 32px` so the rounded ends do not sit flush against the
screen edge.

### Category cards: icon beside the text

New component `src/components/CategoryIcon.jsx` draws three 48x48 inline
SVGs — a phone with signal arcs, a clothes hanger, a house.

**I deliberately did NOT use photos.** The catalogue images come from
Unsplash by ID, and `backend/seed_nepali_products.py` warns in its own
header that nine of fifteen IDs were once composed from memory and the
audit turned up a Prada handbag filed under a Nepali jumper. Inventing
three more IDs would repeat exactly that mistake. Inline SVG also scales
from 68px chips to 52px on a phone, which a JPEG would not.

Markup changed from a flat card to `.category-top` (a flex row) holding
`.category-icon` + `.category-body`. `.category-body` needs
`min-width: 0` — it is a flex child and would otherwise refuse to shrink
below its longest word.

On hover the chip fills solid purple, so `.category-number` mutes to
`--muted` — otherwise there were two competing purple accents side by side.

### The icons took three render passes to get right

Invisible in source, obvious at 3x zoom on a screenshot:

1. **Art too small in its box.** The first drawing used about `x 7..41` of
   48. At 34px in a 72px chip the icon looked lost. Now draws to
   `x 4..44` and renders at 38px in a 68px chip.
2. **Stroke clipped by the viewBox edge.** The phone's outer signal arc was
   centred at `x=36` radius `14` in a 48-wide box: `36+14+1.2 = 51.2`, so
   it ran off and was sliced. Moved to centre `28` radius `11` = `40.2`.
   **Check the outer edge (`centre + radius + strokeWidth/2`), not the
   centre line.**
3. **Centre the union, not the main object.** Phone body at `7..25` plus
   arcs reaching `40` spans `7..40`, midpoint 23.5 — so the phone must sit
   *left* of centre or the arcs leave the box.

Also removed a floating "clothes rail" dash under the hanger (no context,
read as a stray mark), widened the hanger hook (a tight loop read as `?`),
drew the roof and walls as one continuous path (a chevron roof overhung the
walls), and opened the chimney top (a closed rectangle floating over the
roof looked pasted on).
